## 相机与目标相对位置

无 GUI 的初始 30 秒诊断收到 136 帧，4.57 FPS，最长接收间隔 0.865 秒。飞机在地面时图像所有像素为 218。完整飞行中 183 帧不是纯色，已从实际 rosbag 解码保存 `verified_bag_image.png`，另有清晰标记图 `camera_target.png`。因此空中相机内容正常；地面纯灰不能单独用于判断桥故障。

完整飞行图像平均 3.57 FPS，最长间隔 1.181 秒；没有达到模型设置的 30 FPS，不能声称高帧率或无丢帧。相机源时间戳覆盖 28.216 秒，约为接收墙钟时间的 0.371 倍；这只是时间推进比，不是单独测量的 Gazebo `/stats` 实时系数。

本地 `arucotag/model.sdf` 的平面尺寸 0.5×0.5 米，纹理黑色外边界延伸至整张图片边缘。为纹理增加白色检测外边后，OpenCV 在 DICT_4X4_50 中识别 ID 0（它也属于更大的同系列字典）。使用标记边长 0.5 米、模型水平视场角 1.74 rad 和分辨率 1280×960 推导针孔内参：fx=fy=640/tan(0.87)，cx=640，cy=480，畸变假设为零。这是模型推导值，未接收 Gazebo 原生 camera_info 校核。

`/week4/target/pose_camera` 是 **视觉估计**，不是仿真真值，也不是目标相对飞机机体中心的位置。单位米，`camera_optical_frame`：x 向图像右、y 向图像下、z 沿相机视线向前。位置表示标记中心相对相机光心，姿态由 OpenCV 标记 PnP 给出；尚未发布机体/世界 TF 或外参变换。相对深度范围约 0.364～3.146 米，横向范围见 `validation.json`。每帧 `/week4/target/detection` 包含 valid、ID、尺寸、来源和图像时间；无效帧不发布 pose，不把上一次位姿误充当前值。

PX4 本地位置使用 NED：x 北、y 东、z 下；速度字段 vx/vy/vz 同坐标系、单位 m/s。四元数按 PX4 消息顺序 [w,x,y,z] 表达，范数约 1，位置和速度均为有限数值。

## 时间与数据适用范围

MCAP 记录时间为本机 Unix 接收时间；图像及视觉位姿 header 为 Gazebo 仿真时间；PX4 消息保留自身 timestamp。三个时间轴不能直接等同。每话题接收时间、相机源时间、PX4 姿态和位置源时间均未发现倒退。

控制脚本悬停判据等待 PX4 timestamp 推进 20 秒，实际悬停段墙钟约 24.796 秒、所收图像覆盖约 8.58 秒仿真时间。不能将其称作 20 秒 Gazebo 悬停。该包完成了第四周的飞行、图像、遥测和视觉目标采集；用于精确视觉惯性融合或误差定量评估前，仍需建立时钟映射、校核 camera_info/外参并测量丢帧。`flight_overview.png` 按接收时间绘制，仅用于过程检查。

## ROS 2 基础对应关系

节点是运行的功能单元，如图像桥、飞行采集节点、回放播放器。话题是连续消息通道，如 Image 和 VehicleLocalPosition。服务是一次请求/响应，例如节点的 get_parameters 服务；本次飞行指令通过话题和独立 ACK 话题完成，不能把它称为 ROS 服务调用。launch 用一个描述文件启动进程；rosbag 存储消息并按录制时间顺序回放。QoS 必须兼容，采样订阅使用 sensor_data 配置。

如需重复查看（无需重新飞行），在已加载环境的终端运行：

```bash
source /opt/ros/jazzy/setup.bash
source /home/drone/ros2_px4_ws/install/setup.bash
ros2 launch /home/drone/week4_debug/scripts/week4_replay.launch.py
```
